NetApp prend en charge plusieurs composants facultatifs pour améliorer encore les architectures FlexPod Datacenter. Les composants facultatifs sont décrits dans les sous-sections suivantes.


NOTE: Le démarrage SAN est optionnel mais fortement recommandé, car il permet de déplacer les profils de serveur lors de mises à niveau ou de remplacements de matériel.



[[iscsi-boot-option]]
== Option de démarrage iSCSI

Les exigences minimales pour l'option de démarrage iSCSI sont les suivantes :

* Licence/fonctionnalité iSCSI activée sur le contrôleur de stockage NetApp
* Un adaptateur Ethernet 10 Gbit/s à deux ports sur chaque nœud de la paire haute disponibilité du contrôleur de stockage NetApp
* Un adaptateur du serveur Cisco UCS capable de démarrer iSCSI


Les figures suivantes illustrent un exemple de centre de données FlexPod avec un système modulaire X-Series et des serveurs rack C-Series pour la configuration iSCSI basée sur IP.

[[fc-boot-with-cisco-mds]]
== Démarrage FC avec Cisco MDS

Pour offrir une évolutivité accrue grâce à un réseau SAN dédié, FlexPod prend en charge le FC via les commutateurs Cisco MDS. L’option de démarrage SAN FC via Cisco MDS requiert les licences et le matériel suivants :

* Au moins deux ports FC par contrôleur de stockage NetApp ; un port pour chaque structure SAN
* Une licence FC sur chaque contrôleur de stockage NetApp.
* Un adaptateur dans le serveur Cisco UCS capable de démarrer en FC.


La figure suivante illustre un exemple de centre de données FlexPod avec un système modulaire X-Series et des serveurs rack C-Series pour une configuration SAN basée sur FC avec des commutateurs MDS.

image:dc-tech-spec_image16.png["FlexPod Datacenter pour la connectivité SAN basée sur FC"]

Pour plus d'informations sur cette configuration, consultez link:https://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/UCS_CVDs/flexpod_m7_imm_vmware_design.html#PhysicalTopology["FlexPod Datacenter avec Cisco UCS M7 IMM, VMware vSphere 8.0 et NetApp ONTAP 9.12 Guide de conception"^].

[[end-to-end-fc-nvme]]
== FC-NVMe de bout en bout

Une solution FC-NVMe de bout en bout étend de manière transparente l'infrastructure SAN existante d'un client pour les applications temps réel, tout en améliorant les IOPS et le débit grâce à une latence réduite. Un réseau SAN FC 32G existant peut être utilisé pour transporter simultanément des charges de travail NVMe et SCSI.

Pour plus d'informations sur cette configuration, consultez link:https://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/UCS_CVDs/flexpod_m7_imm_vmware_design.html#PhysicalTopology["FlexPod Datacenter avec Cisco UCS M7 IMM, VMware vSphere 8.0 et NetApp ONTAP 9.12 Guide de conception"^].



[[cisco-ucs-x-series-direct-and-direct-attached-aff-asa-fas-for-fc-and-ip-based-san]]
== Cisco UCS X-Series Direct et AFF/ ASA/ FAS en connexion directe pour SAN basé sur FC et IP

NetApp storage controllers peuvent être connectés directement aux interconnexions de structure Cisco UCS sans aucun commutateur SAN en amont. FlexPod prend en charge le démarrage FC et iSCSI avec UCS X-Series Direct.

La configuration matérielle et de licence est la suivante :

* Une licence de protocole est requise sur le contrôleur de stockage NetApp.
* Un adaptateur Cisco UCS (initiateur) est requis sur le serveur. Pour obtenir la liste des adaptateurs Cisco UCS pris en charge, consultez le NetApp https://imt.netapp.com["IMT"^].
* Un adaptateur cible est requis sur le contrôleur de stockage NetApp.

image:dc-tech-spec_image13.png["Topologie ASA UCS X-Series Direct et ASA à connexion directe pour SAN basé sur IP"]

*Notes:*

* Cisco UCS est configuré en mode de commutation Ethernet.
* Les ports iSCSI de la cible aux interconnexions de fabric sont configurés en tant que ports de stockage Ethernet pour les données iSCSI.


La figure suivante illustre une topologie UCS X-Series Direct et ASA à connexion directe pour SAN basé sur IP et FC.

*Notes:*

[[metrocluster]]
== MetroCluster

FlexPod MetroCluster IP avec solution d’infrastructure VXLAN Multi-Site se compose de deux FlexPods, situés sur deux sites séparés par une certaine distance, mais connectés et appariés pour offrir une solution de centre de données hautement disponible, hautement flexible et hautement fiable, capable d’assurer la continuité des activités même en cas de défaillance d’un site. La distance maximale prise en charge entre les sites est d’environ 435 miles (700 km).

Dans la solution IP FlexPod MetroCluster, la solution Cisco VXLAN Multi-Site permet d’interconnecter et de gérer de manière centralisée des fabrics VXLAN déployés dans des centres de données distincts et géographiquement dispersés. NetApp MetroCluster IP offre une solution de réplication synchrone entre deux clusters de stockage NetApp, assurant une haute disponibilité du stockage et une reprise après sinistre dans un campus ou une zone métropolitaine. La solution vous permet de concevoir un cloud privé VMware vSphere basé sur une infrastructure intégrée et distribuée, et de fournir une solution unifiée permettant à plusieurs sites de fonctionner de manière similaire à un site unique, tout en protégeant les services de données contre divers scénarios de point de défaillance unique, y compris la panne complète d’un site.

[[snapmirror-active-sync-solution-for-flexpod-metrocluster-ip-solution]]
=== Solution de synchronisation active SnapMirror pour la solution IP FlexPod MetroCluster

En utilisant la technologie Snapshot de NetApp dans le logiciel NetApp ONTAP, les services de données SAN critiques peuvent être rapidement restaurés à partir des données de sauvegardes basées sur Snapshot.

* Les deux clusters ONTAP déployés sur deux sites différents sont appariés et configurés avec SnapMirror active sync pour la réplication synchrone des données et la reprise après sinistre.
* Le ONTAP Mediator est déployé dans un troisième domaine de défaillance, comme illustré dans la figure ci-dessous. Avec les clusters, le ONTAP Mediator complète le quorum pour la solution SnapMirror active sync.
* Le médiateur ONTAP reçoit les informations d'intégrité des clusters et nœuds ONTAP appariés et orchestre la communication entre eux afin de déterminer leur état. Les données d'intégrité aident les clusters à distinguer les différents types de pannes et à décider s'il convient d'effectuer un basculement automatique.


image:dc-tech-spec_image18.png["Composants de la solution SnapMirror active sync pour la solution IP FlexPod MetroCluster"]

Un groupe de cohérence, représenté sur le schéma, comprend trois LUN spécifiques à l'application où les données sont répliquées de manière synchrone vers le cluster homologue par SnapMirror active sync.
